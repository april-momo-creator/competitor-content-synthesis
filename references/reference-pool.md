# Reference Pool Curation

Build a production asset, not a bookmark dump.

## Default Size

Retain 10–25 references for a full run. Use fewer when evidence is thin and more only when the production program genuinely needs distinct categories. Never fill a quota with weak examples.

## Useful Reference Categories

- Direct-competitor positioning or proof.
- Direct-competitor UGC or creator expression.
- Indirect-competitor workaround, complaint, or substitute behavior.
- Aspirational hook, format, visual system, or soft integration.
- Strong user-moment or pain-language reference.
- High-intent comment or objection reference.
- Slideshow or sequence structure.
- Negative or risk reference that shows what to avoid.

Balance categories according to the decision question. Do not force equal representation.

## Reference Record

Every retained item must include:

| Field | Requirement |
|---|---|
| `reference_id` | Stable identifier |
| `content_id` | Link to the source analysis record |
| `source_url` | Original source link |
| `platform` | Source platform |
| `source_type` | Owned, UGC, creator, community, or review |
| `competitor_type` | Direct, indirect, aspirational, or unknown |
| `persona` | Intended or observed audience |
| `user_moment` | Situation or job represented |
| `pattern_tags` | Pattern IDs supported by this item |
| `why_selected` | Evidence-based reason for keeping it |
| `transferable_element` | Principle, structure, or execution that can be adapted |
| `do_not_copy` | Wording, visual, claim, identity, or context that must remain original |
| `possible_adaptation` | A product-specific, original direction |
| `evidence_label` | Verified, inferred, or needs validation |
| `risk_level` | Low, medium, high, unknown |
| `observed_at` | Evidence snapshot date |

## Curation Rules

1. Keep an item only if it supports a pattern, opportunity, production question, or explicit negative lesson.
2. Prefer independent examples over repeated uploads of the same creative.
3. Keep source URLs and concise observations; do not reproduce full third-party scripts, captions, image sets, or transcripts.
4. Distinguish structural inspiration from visual or verbal copying.
5. Include counterexamples when they prevent overgeneralization.
6. Remove items whose only value is high reach without product, audience, or format relevance.

## Stop Conditions

Stop adding references when:

- Each priority pattern has at least two useful supporting references.
- Each priority opportunity has at least one user-evidence reference and one execution reference.
- New items repeat an existing lesson without adding a new persona, format, proof type, or boundary.
- Every retained item has a clear downstream use.
