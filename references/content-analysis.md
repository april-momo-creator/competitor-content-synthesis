# Content Analysis Protocol

Analyze content to explain observable structure and generate testable hypotheses. Do not claim a hidden cause from public metrics alone.

## Select the Analysis Sample

Build a balanced sample rather than a leaderboard:

- Positive outliers within an account.
- Low-follower breakouts.
- High-intent examples.
- Typical baseline posts.
- Comparable underperformers.
- Different source types: owned, UGC, creator, community, and review when available.
- Relevant direct, indirect, and aspirational competitors.

Exclude or isolate:

- Content outside the target audience or market.
- Paid or boosted content when it cannot be compared fairly.
- Reposts without identifiable original context.
- Old content whose platform format is no longer representative, unless used historically.
- Posts with no strategic relevance beyond large reach.

## Per-Content Analysis Card

Record:

| Field | Question |
|---|---|
| Source and provenance | Where did this come from, and when was it observed? |
| Context | Platform, account, source type, competitor type, market, publication date |
| Performance evidence | How does it compare with the account baseline or follower base? |
| Topic | What is the literal subject? |
| Content angle | What strategic interpretation of the topic is used? |
| Target persona | Who is expected to recognize themselves? |
| User moment | What situation, trigger, or job is depicted? |
| Hook | What does the first second, line, or frame promise? |
| Structure | How does attention move from hook to proof to payoff? |
| Proof | Demo, result, testimonial, comparison, authority, social proof, or none |
| Product exposure | When and how does the product enter? |
| CTA | What action is requested? |
| Audience response | What visible questions, objections, or intent signals appear? |
| Transferable element | Which structure or principle can be adapted? |
| Non-transferable element | Which brand asset, claim, persona, cultural cue, or execution should not be copied? |
| Risk | Copyright, unsupported claim, platform compliance, brand safety, or audience mismatch |
| Evidence label | Verified, inferred, or needs validation |

## Structure Vocabulary

Use precise labels when useful:

- Problem → tension → reveal → proof → CTA
- Before → intervention → after
- List → ranking → recommendation
- Question → answer → demonstration
- Mistake → correction → result
- Story → turning point → lesson
- Comparison → decision criteria → winner by use case
- Comment reply → direct answer → proof
- Mood or identity cue → routine → soft product integration

## Slideshow or Sequence Analysis

Assign a role to every frame:

- `hook`
- `context`
- `build`
- `proof`
- `spike`
- `soft-ad`
- `cta`
- `mood-setter`

Also record:

- Sequence type: list, steps, story, comparison, Q&A, mood board.
- Visual movement: zoom, pan, progression, independent frames.
- Information load per frame.
- Reveal timing.
- Product placement timing.
- Whether the structure survives without copying the original wording or visuals.

## Analysis Quality Check

Reject explanations such as “it went viral because it used AI,” “the hook is good,” or “people like relatable content.” Replace them with a specific observation, a comparison, and a testable hypothesis.

Example:

```text
Observation: Three posts open with a role-specific failure moment before naming the tool.
Comparison: Similar feature-first posts on the same accounts remain near baseline.
Inference: Recognition of the failure moment may improve first-frame retention.
Test: Run the same product proof with a failure-moment hook and a feature-first hook.
```
